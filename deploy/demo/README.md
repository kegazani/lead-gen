# Локальное демо

Из корня репозитория с существующим `.env`:

```bash
docker compose -p lead-gen-demo -f compose.demo.yaml up -d --build --wait --wait-timeout 240
```

Нужны `POSTGRES_PASSWORD`, `FIRECRAWL_API_KEY`, `LLM_API_KEY`.
Для DeepSeek используются `LLM_BASE_URL` и `LLM_MODEL`; пароль и логин оператора
берутся из `CONSOLE_PASSWORD`/`CONSOLE_USER` (по умолчанию `admin`/`admin`).
Пароль записывает одноразовый helper в отдельный том с правами runtime-пользователя;
приложения читают файл. `.env` в Git не добавляется.
Служебный образ собирается один раз сервисом `app`; `demand` использует этот же
образ без отдельной сборки и без загрузки тега из внешнего реестра.

- Клиент: http://localhost:18000/login — зарегистрируйте свою компанию.
- Оператор: http://localhost:18000/admin/console — одобрите регистрацию и профиль.
- Заявки: http://localhost:18000/intake/validation — откройте и одобрите заявку,
  при желании задав цель 25. «Взять на проверку» открывает проверку заявки;
  «Одобрить и начать поиск» автоматически запускает краулинг. После одобрения
  нажмите «Открыть поиск и результат»: стадия, статус и письма обновляются
  каждые 5 секунд. Число найденных обновляется после завершения раунда поиска;
  начальный 0 ещё не означает, что ничего не найдено.
- Лиды: http://localhost:18000/lead-console/leads — все сохранённые компании,
  включая компании без email.
- Карточки: http://localhost:18000/lead-console/cards — по умолчанию группа «Все».
  Если браузер сохранил пустую группу, нажмите «Показать все сохранённые компании».
  Списки обновляются каждые 5 секунд; email-экспорты содержат только компании с адресом.
- Отчёты: http://localhost:18000/reporting/dashboard.

Порт меняется через `LEADGEN_DEMO_HTTP_PORT` в `.env`.
После входа оператором откройте «Тенант», найдите свою компанию со статусом
«активен» и нажмите «Выбрать». Выбор сохраняется для заявок, лидов, пользователей
и отчётов; повторный вход между разделами не требуется. Пока компания не выбрана,
«Заявки» и «Исполнение» ведут на этот список. Если в адресе или cookie остался tenant
из прежней базы, список компаний остаётся доступным: выберите существующую компанию.
Компания «на проверке» сначала требует одобрения в «Регистрациях».

В карточке исполнения блок «Подробности исполнения» показывает раунд добора,
число лидов из существующей базы и нового обхода, время работы, активный шаг,
попытку и давность подтверждения от исполнителя. Старое исполнение без записи
происхождения показывает неизвестность, а не предполагаемый источник.
Счётчик «Писем сохранено» и блок «Сформированные письма» обновляются по данным
хранилища: уже готовые письма видны, даже когда генерация остальных ещё идёт.

Отчёты показывают накопленную аналитическую проекцию; в демо без доставки писем
показатели доставки могут быть пустыми. Это не заменяет фактические счётчики
поиска и писем на странице заявки.

Пересборка выполняется той же командой запуска. После изменения nginx-конфигурации
перезапустите `web`, чтобы он перечитал маршруты:

```bash
docker compose -p lead-gen-demo -f compose.demo.yaml restart web
```

Проверка и логи:

```bash
docker compose -p lead-gen-demo -f compose.demo.yaml ps
docker compose -p lead-gen-demo -f compose.demo.yaml logs --tail=100 app demand
```

Остановка с сохранением данных:

```bash
docker compose -p lead-gen-demo -f compose.demo.yaml stop
```

Это отдельный dev-контур существующего демо-пути: свои БД, RabbitMQ, Temporal и
постоянные тома. Он не использует production `POSTGRES_GREEN_DATA_VOLUME`,
`LEADGEN_RELEASE_STATE_VOLUME`, signing keys или пути `/Users/...`.
Ранее созданные клиенты и заявки штатного Compose остаются в его БД;
в демо регистрируется новый клиент. SMTP-доставка не запускается.
Реальный поиск зависит от доступности провайдеров и сайтов; недобор отображается.
