# Исследовательский поиск

Отдельный, явно включаемый путь change `intelligent-lead-research` в ветке
`concept/intelligent-lead-research`. Он использует человеческую заявку,
LLM-планировщик, Firecrawl и постоянную исследовательскую память PostgreSQL.
Полная программа change, включая собственный browser/OCR, формы, inbound и
производство/отправку материалов из новой памяти, ещё не считается завершённой.

## Запуск рядом с существующим кодом демо

Нужны Docker Compose и `.env`, описанный в [инструкции демо](../demo/README.md).
Используются `POSTGRES_PASSWORD`, `CONSOLE_USER`, `CONSOLE_PASSWORD`,
`FIRECRAWL_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`.
Рекомендуемый для текущего провайдера `LLM_MODEL=deepseek-flash`.

```sh
git switch concept/intelligent-lead-research
git pull --ff-only origin concept/intelligent-lead-research
docker compose -f compose.demo.yaml -f compose.research.yaml up -d --build
```

Открыть `http://localhost:18000/admin/console`, выбрать активную компанию,
создать **новую** заявку, открыть её проверку и перейти в исследование.
Количество компаний и единицу результата выбирает человек. Рынок по умолчанию
Россия; можно выбрать страны и языки. Выбор рынка ограничивает поиск, но не
означает, что Firecrawl использует IP данной страны.

После одобрения экран показывает сохранённые компании, проверку критериев,
контакты, состояние действий и Firecrawl. У компании без контактов есть досье
и открытая потребность в контактах. Источник, цитата и состояние подтверждения
видны в досье. Пауза, продолжение и отмена используют версию миссии.

Заявку, уже запущенную старым исполнителем, нельзя переключить на новый путь.
Это предотвращает повторный обход и второй расход по тому же поручению.
Параметры одобренного исследования сохраняются даже при ошибке планировщика;
повторный запуск использует тот же человеческий выбор.

## Дополнительный SearXNG

Опциональный metasearch источник включается явно. Из корня репозитория:

```sh
python3 deploy/research/searxng/generate-settings.py
export LEADGEN_RESEARCH_SEARXNG_URL=http://searxng:8080
export LEADGEN_RESEARCH_SEARXNG_ENGINES=duckduckgo,brave
docker compose -f compose.demo.yaml -f compose.research.yaml \
  -f deploy/research/searxng/compose.yaml --profile searxng up -d --build
```

Для последующих запусков эти две переменные можно сохранить в `.env`. Список
engines должен совпадать с настройками экземпляра; генератор принимает
`RESEARCH_SEARXNG_ENGINES`. SearXNG ищет URL, а разрешённый Firecrawl source
читает страницы. Денежного ledger для SearXNG нет; попытки, время и объём
ответов ограничены технически. По умолчанию URL пустой и источник выключен.

В облачной проверке контейнер и JSON API работали, но штатный proxy отклонил
upstream engines (`CONNECT 403`); успешный внешний поиск пока не подтверждён.
Настройка существующего proxy/CA, закреплённый образ и фактический результат
описаны в [инструкции SearXNG](searxng/README.md).

## Ограничения и учёт

`FIRECRAWL_MAX_CREDITS` — потолок Firecrawl для отдельного поручения
(в Compose по умолчанию 150). `FIRECRAWL_ACCOUNT_MAX_CREDITS` — общий потолок
аккаунта в постоянном учёте; `0` означает, что дополнительный денежный потолок
оператор не установил. Баланс провайдера проверяется перед платным вызовом.
Неизвестный исход сохраняет резерв до сверки, повтор не списывает новый резерв.
`LEADGEN_RESEARCH_FIRECRAWL_ACCOUNT` — стабильное имя аккаунта; при рестарте его
не менять, иначе получится отдельная область учёта.

Overlay отключает старые платные вызовы Firecrawl в `app` и `demand`.
Прямой запуск с `-research-enabled` также требует `-research-only-provider`;
без этого сочетания сборка отклоняется до открытия исследовательской БД.
Другие приложения, использующие тот же ключ, не входят в локальный учёт.
Денежных лимитов для LLM и остальных инструментов здесь нет.

Учтённые credits успешных операций рассчитываются по текущему тарифу адаптера.
Это не индивидуальная выписка расхода провайдера: общий баланс запрашивается
отдельно, а неизвестный исход удерживает резерв до сверки.

Технические ограничения: `LEADGEN_RESEARCH_MAX_ACTIONS` (100 по умолчанию),
`LEADGEN_RESEARCH_TIMEOUT` (1 час), размер документа 256 КиБ, до двух попыток,
до двух уровней переходов. Это пределы исполнения, а не требуемое число лидов.
`LEADGEN_RESEARCH_CONTACT_FRESHNESS` (720 часов) задаёт срок актуальности
наблюдения контакта; он не подтверждает доставляемость email.

Обычные единицы результата — компания и компания с контактом. Готовность email
к отправке требует отдельного решения downstream policy; пока этот контур
не подключён, интерфейс не предлагает такую единицу. Новые исследовательские
досье находятся на экране заявки; legacy вкладка лидов и генератор писем
пока используют свою прежнюю модель.

Документы, миссии и receipts хранятся в red БД `leadgen_lead_red`, в отдельных
схемах их владельцев. Green содержит человеческий выбор режима и ссылки.
Миграции этого пути применяются только в явно выбранном demo/legacy DB policy;
production `runtime-only` intake не переводится на них автоматически.

## Возврат к прежнему демо

Остановить либо отменить активные исследования через интерфейс, затем:

```sh
docker compose -f compose.demo.yaml up -d --build
```

Тома сохраняются; удалять их не требуется. Исследовательские записи остаются
в PostgreSQL, но старый исполнитель их не продолжает.
