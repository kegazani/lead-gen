## Context

Общий слой оформления серверных экранов (`frontend/components/static/console.css`) раздаётся всем сервисам по `/static/console.css` (requirement «Общий слой оформления серверных экранов»). Тема переключается скриптом `theme.js` через атрибут `data-theme`; токены светлой темы объявлены в `:root`, тёмной — в `:root[data-theme="dark"]`. Тесты общего слоя (`contrast_test.go`, `static_test.go`, `a11y_test.go`) читают токены и правила прямо из файла: контраст подписей статусов на их подложках, формы маркеров, наличие правил экрана операций и отключение движения. CSP консоли запрещает встроенные стили и скрипты.

Направление оформления выбрано пользователем по интерактивному макету: «матовое стекло» и графитовый акцент.

## Goals / Non-Goals

**Goals:**

- Заменить фиолетово-градиентный вид на матовое стекло, не меняя классов разметки: все экраны получают новый вид одним файлом.
- Убрать машинные коды из интерфейса механизмом, который переиспользуют все контексты.
- Привести экраны заявок к виду «таблица / подпись — значение / панель решения».

**Non-Goals:**

- Публичные страницы edge, разметка экранов операций и топологии, перевод подписей на другие языки.
- Имена тенантов вместо идентификаторов: в контексте `request-fulfillment` нет контракта чтения названия тенанта, поэтому идентификатор показывается с подписью «Клиент:» — честно, без выдуманного имени.

## Decisions

### Решение 1. Стекло как набор токенов и одно групповое правило

Материал задаётся токенами (`--glass`, `--glass-border`, `--glass-hi`, `--glass-lo`, `--glass-blur`) и одним групповым правилом для всех поверхностей. `--surface` остаётся непрозрачным эквивалентом стекла на подложке: по нему тесты считают контраст, им же заменяется стекло в блоке `@supports not (backdrop-filter: …)`. Так контраст проверяется на том, что видит человек в худшем случае.

**Альтернатива:** SVG-фильтр преломления (`backdrop-filter: url(#…)`) — отклонён: работает только в Chromium и требует встроенной разметки, которую запрещает CSP.

### Решение 2. Графит вместо цветного акцента

Акцент хрома — `--accent` (графит), текст на нём — `--btn-fg`. Акцент не пересекается с палитрой статусов, поэтому цвет в интерфейсе всегда означает статус. «Письмо отправлено» переведено из фиолетового в синий: фиолетовый исключён из оформления целиком.

### Решение 3. Подписи кодов — функция `label` общего слоя

`Messages.Label(prefix, code)` нормализует код так же, как `StatusClass` (нижний регистр, разделители — дефис), и ищет ключ `prefix.code` в каталоге. Найден — подпись; не найден — сам код. Функция шаблонов `label` принимает код любого строкового типа (`fmt.Sprint`), поэтому доменные именованные строки передаются без преобразования в адаптере. Подписи живут в каталогах контекстов-владельцев экранов; общий слой доменных терминов не получает.

В `lead-management` подписи уже строятся в Go (`stageLabel`), поэтому стадия, состояние задания и письма подписываются функциями представления в `views.go` — по существующему образцу контекста.

**Альтернатива:** `text (printf "…%s" .Phase)` — отклонено: неизвестный код превращался бы в ключ каталога на экране.

### Решение 4. Проверки экранов по видимому тексту

Сведения на экране утверждения теперь — пары `dt/dd`, поэтому строка «Найдено лидов: 7» есть в видимом тексте, но не подряд в разметке. Тесты экрана сравнивают видимый текст (`visibleText`: теги → пробел, пробелы схлопнуты), а не разметку; смысл проверок (найдено, цель, недобор, честная недоступность) не меняется. Очередь несёт «Найдено лидов: N» в `aria-label` прогресса.

## Risks / Trade-offs

- [Размытие нагружает слабые машины] → размытие только у статичных поверхностей, без анимации размытия; при `prefers-reduced-motion` анимации отключены.
- [Глобальные правила для `.page table` и полей могут задеть экраны с собственной вёрсткой] → таблицы внутри панелей и карточек сбрасывают стекло; проверено скриншотами всех золотых рендеров в обеих темах.
