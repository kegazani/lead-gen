## Purpose

Группирует записи пула в сегменты для адресных кампаний: статические по атрибутам, динамические по поведению, комбинированные по условиям, с исключающими сегментами и фиксацией состава на момент запуска кампании. Выполняется в контуре клиента и не использует условие открытия.

## ADDED Requirements

### Requirement: Статические сегменты по атрибутам

Система SHALL формировать статические сегменты по атрибутам записи: отрасль, размер компании, регион, источник, статус адреса.

#### Scenario: Сегмент по отрасли

- **WHEN** задано условие по отрасли
- **THEN** состав сегмента включает записи, соответствующие условию

#### Scenario: Сегмент по статусу адреса

- **WHEN** задано условие по статусу проверки адреса
- **THEN** состав сегмента включает записи с указанным статусом

#### Scenario: Сегмент по нескольким атрибутам

- **WHEN** задано условие одновременно по нескольким атрибутам
- **THEN** состав соответствует всем заданным атрибутам одновременно

### Requirement: Динамические сегменты по поведению

Система SHALL формировать динамические сегменты по поведению записи: перешёл по ссылке, ответил, отказался, не реагировал.

#### Scenario: Сегмент по переходу

- **WHEN** задано условие «перешёл по ссылке»
- **THEN** состав сегмента включает записи с зафиксированным переходом

#### Scenario: Сегмент по ответу

- **WHEN** задано условие «ответил»
- **THEN** состав сегмента включает записи с полученным ответом

#### Scenario: Сегмент по отсутствию реакции

- **WHEN** задано условие «не реагировал» с указанием периода
- **THEN** состав включает записи без переходов, ответов и отказов за период

### Requirement: Отсутствие условия открытия

Система SHALL NOT предоставлять условие по факту открытия письма. Попытка задать такое условие SHALL отклоняться.

#### Scenario: Попытка задать условие открытия

- **WHEN** в условии сегмента указан признак открытия письма
- **THEN** система отклоняет условие и сообщает, что сигнал открытия не собирается

#### Scenario: Отсутствие условия в перечне доступных

- **WHEN** оператор открывает перечень доступных условий
- **THEN** условия по открытию в перечне нет

### Requirement: Комбинированные условия

Система SHALL поддерживать комбинирование условий по атрибутам и поведению операторами И, ИЛИ, НЕ, включая вложенные группы.

#### Scenario: Комбинация И

- **WHEN** заданы два условия, объединённые оператором И
- **THEN** состав соответствует обоим условиям

#### Scenario: Комбинация ИЛИ

- **WHEN** заданы два условия, объединённые оператором ИЛИ
- **THEN** состав соответствует хотя бы одному из них

#### Scenario: Отрицание НЕ

- **WHEN** условие объединено с отрицанием НЕ
- **THEN** состав соответствует обратному условию

#### Scenario: Вложенные группы

- **WHEN** условия объединены во вложенные группы
- **THEN** состав рассчитывается по заданной вложенности

### Requirement: Автоматический пересчёт динамических сегментов

Система SHALL пересчитывать состав динамических сегментов при изменении данных без ручного запуска.

#### Scenario: Изменение поведения записи

- **WHEN** у записи появился ответ или переход
- **THEN** состав соответствующих динамических сегментов обновляется автоматически

#### Scenario: Изменение статуса адреса

- **WHEN** статус адреса изменился по результату проверки или отказа
- **THEN** сегменты, использующие статус, пересчитываются

#### Scenario: Пересчёт не блокирует работу

- **WHEN** выполняется пересчёт состава
- **THEN** ранее построенные сегменты остаются доступны для использования

### Requirement: Исключающие сегменты с приоритетом

Система SHALL поддерживать исключающие сегменты: стоп-лист, отписавшиеся, адреса со статусами `invalid`, `disposable`, `abuse`. Исключающие условия SHALL иметь приоритет над включающими и SHALL NOT быть отменены комбинацией включающих условий.

#### Scenario: Запись в стоп-листе

- **WHEN** запись находится в стоп-листе
- **THEN** она исключена из состава любого сегмента, включая те, чьим условиям соответствует

#### Scenario: Включающее условие совпадает с исключённой записью

- **WHEN** запись удовлетворяет включающему условию, но входит в исключающий сегмент
- **THEN** запись не попадает в состав сегмента

#### Scenario: Исключение применяется ко всем сегментам

- **WHEN** заданы несколько сегментов кампании
- **THEN** исключающие условия применяются к каждому из них

### Requirement: Использование сегмента как цели кампании

Система SHALL позволять использовать сегмент как цель кампании. Состав сегмента SHALL фиксироваться на момент запуска кампании.

#### Scenario: Сегмент выбран целью кампании

- **WHEN** сегмент выбран целью кампании
- **THEN** кампания использует его состав

#### Scenario: Состав изменился после запуска

- **WHEN** состав сегмента изменился после запуска кампании
- **THEN** текущая кампания продолжает работу с зафиксированным составом

#### Scenario: Изменённый состав применяется к следующей кампании

- **WHEN** запущена новая кампания по тому же сегменту
- **THEN** используется актуальный состав на момент её запуска

#### Scenario: Пустой сегмент

- **WHEN** состав сегмента пуст
- **THEN** кампания не запускается и оператору сообщается о пустом составе

### Requirement: Минимальный набор сегментов первой версии

Система SHALL предоставлять набор сегментов, доступных без предварительной настройки: по атрибутам — отрасль, размер, регион, источник, статус адреса; по поведению — ответил, перешёл, не реагировал, отказался.

#### Scenario: Доступность набора по умолчанию

- **WHEN** оператор открывает перечень сегментов
- **THEN** сегменты из набора первой версии доступны без настройки

#### Scenario: Добавление сегмента сверх набора

- **WHEN** требуется сегмент вне набора первой версии
- **THEN** он задаётся условием и сохраняется для повторного использования

### Requirement: Работа в контуре клиента

Сегментация SHALL выполняться в контуре клиента. Система SHALL NOT переносить состав сегментов и записи пула на сторону платформы.

#### Scenario: Расчёт состава

- **WHEN** строится состав сегмента
- **THEN** расчёт выполняется в контуре клиента

#### Scenario: Аудит хранилищ платформы

- **WHEN** выполняется аудит хранилищ платформы
- **THEN** состава сегментов и записей пула на стороне платформы не обнаружено
