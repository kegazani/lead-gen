## Context

См. `proposal.md` и дельты `client-request`, `client-portal`, `console-appearance`. Заявку создаёт клиентский HTTP handler в `platform-governance`, команда проходит через контракт `request-intent` к агрегату `Request` в `request-fulfillment`. Snapshot заявки хранится сериализованным в PostgreSQL; выдача операторских списков строится владельцем заявки. Серверные шаблоны сервисов используют общие `frontend/components` и общий `console.css`.

## Goals / Non-Goals

**Goals:** имя заявки проходит весь путь создания, хранения, чтения и отображения; длинные описательные поля таблиц имеют предсказуемое символьное сокращение и сохраняют полный текст для просмотра.

**Non-Goals:** изменение текста оффера, ограничение длины самого оффера при хранении, обрезка данных в API/экспорте, перестройка таблиц или изменение статусов/идентификаторов.

## Decisions

### 1. Имя — поле агрегата `Request`

Owning context — `request-fulfillment`, aggregate root — `Request`. Новое значение добавляется в команду создания, доменный snapshot и query view. Новый domain event не требуется: имя не меняет переход статуса и событие `request-submitted` остаётся фактом подачи заявки. Поле включается в сравнение `SameSubmission`, чтобы повтор с тем же идентификатором и другим именем был конфликтом.

Лимит измеряется Unicode code points после `strings.TrimSpace`; верхняя граница — 100, нижняя — 1. Ограничение задаётся в домене, а HTML `maxlength` и клиентская подпись служат подсказкой, не заменяя серверную проверку.

### 2. Совместимость старых snapshot

SQL-миграция не нужна: PostgreSQL-адаптер уже хранит snapshot целиком, а новое поле сериализуется рядом с другими полями. При восстановлении snapshot без имени (legacy-запись) имя выводится детерминированно из первых 100 Unicode code points текста текущего оффера; это сохраняет доступность старых заявок и не переписывает исходные записи до следующего штатного сохранения. Новые команды создания без имени по-прежнему отклоняются.

### 3. Имя передаётся через контракт `request-intent`

`platform-governance` принимает имя в форме и передаёт его через команду use case и опубликованный контракт `request-intent`; `request-fulfillment` остаётся единственным владельцем и валидирует его повторно. Ошибка домена возвращается в форму с введёнными полями. Существующие потребители контракта и тестовые fixtures обновляются явно.

### 4. Общее сокращение шаблонов по Unicode code points

В общем модуле `frontend/components` добавляется переиспользуемая функция сокращения строки, доступная серверным шаблонам через общий `FuncMap`. В шаблонах таблиц она применяется только к описательным пользовательским/провайдерским текстовым значениям; идентификаторы, статусы, числовые метрики и кнопки остаются без изменений. Для сокращённого значения полный исходный текст остаётся в `title`, а доступное имя содержит исходную строку. `console.css` задаёт единое отображение многоточия и не меняет серверные данные.

Альтернатива — ограничивать все `td` общей CSS-шириной: она не гарантирует лимит символов и может скрывать действия или структурированные значения, поэтому не выбирается. Альтернатива — резать данные при записи: она необратимо теряет текст и не подходит.

## Risks / Trade-offs

- **Старые заявки не имеют заданного клиентом имени** → query и rehydration используют стабильное имя из начала оффера; новые заявки проходят строгую доменную проверку.
- **Не все значения ячеек являются описаниями** → сокращение включается только в перечисленных шаблонах для текстовых полей, а не глобально для любого `td`.
- **Заголовок браузера может быть неудобен на сенсорном устройстве** → полный текст также должен быть доступен клавиатурой/экранным диктором и оставаться на странице детали заявки.

## Migration Plan

Миграция схемы базы не требуется. Сначала обновляются контракт и владелец заявки с обратной совместимостью чтения старых snapshot, затем клиентская форма и UI-представления. Откат кода безопасен для данных: старый бинарник игнорирует неизвестное JSON-поле snapshot; добавленное поле может перестать показываться, но не ломает сохранённый оффер.
