## 1. Основание и правовая рамка

- [ ] 1.1 Включить движок в объём юридической проверки задачи 1.1 рамки: подтвердить, что заключение покрывает приём слота от контрагента, отправку напоминаний и публичную страницу выбора слота (верификация: заключение приложено, перечень покрытых механик содержит все три пункта)
- [ ] 1.2 Согласовать способ утверждения плана с требованием рамки об индивидуальном решении внутри пакета. Отдельного правила в рамку не вносится; если способ должен стать общим правилом, расширение требования рамки выносится отдельно (верификация: правило в рамке не изменено; `spec.md` и `design.md` изменения ссылаются на существующее требование, а не на пакетное подтверждение из BRD §1.1)
- [ ] 1.3 Опубликовать политику обработки персональных данных для страницы выбора слота (верификация: страница содержит ссылку на политику, наличие проверяется тестом)

## 2. Модель данных и приём сведений

- [ ] 2.1 Реализовать сущность звонка в красной зоне: время, участники, источник, автор записи, ссылка, состояние (верификация: тест размещает запись в красной зоне, попытка записи в зелёную зону завершается ошибкой)
- [ ] 2.2 Реализовать ключ идемпотентности «источник + внешний идентификатор» (верификация: тест двух событий с одним ключом даёт одну запись звонка)
- [ ] 2.3 Реализовать сведение сведений из нескольких источников к одной записи без перезаписи решений человека (верификация: тест «страница выбора слота, затем вебхук CRM» даёт одну запись с дополненными полями)
- [ ] 2.4 Реализовать приём из четырёх поддерживаемых источников с журналированием факта приёма (верификация: тест по каждому источнику создаёт запись с указанием источника и времени приёма)
- [ ] 2.5 Реализовать отказ в приёме для источника вне списка (верификация: тест с неизвестным источником возвращает отказ, фиксирует причину и не создаёт запись звонка)

## 3. Состояния и подтверждение

- [ ] 3.1 Реализовать модель состояний: ожидание слота, слот подтверждён, подтверждён вне платформы, назначен, состоялся, не состоялся, перенесён, отменён (верификация: тест набора переходов проходит, недопустимые переходы отклоняются)
- [ ] 3.2 Реализовать подтверждение слота контрагентом (верификация: тест выбора слота переводит звонок в «слот подтверждён» с временем слота и временем подтверждения)
- [ ] 3.3 Реализовать подтверждение встречи, согласованной вне платформы, с обязательным основанием и автором (верификация: тест без основания оставляет состояние «ожидание слота», с основанием переводит в «подтверждён вне платформы»)
- [ ] 3.4 Запретить достижение состояния «назначен» без утверждённого плана коммуникации (верификация: тест перехода в «назначен» при неутверждённом плане отклоняется)
- [ ] 3.5 Реализовать ручную фиксацию исхода звонка (верификация: тест фиксирует «состоялся» и «не состоялся» с автором, а переход по ссылке на конференцию состояние не изменяет)

## 4. Утверждение плана коммуникации

- [ ] 4.1 Реализовать формирование черновика плана коммуникации после подтверждения звонка в любом из двух подтверждённых состояний (верификация: тест создаёт черновик, содержащий инвайт и расписание напоминаний)
- [ ] 4.2 Реализовать утверждение плана через очередь утверждений рамки, без собственного механизма утверждения (верификация: прямой вызов API отправки без утверждения не исполняет действие)
- [ ] 4.3 Реализовать сброс утверждения при изменении времени, текста или состава напоминаний (верификация: тест изменения плана возвращает его в состояние ожидания утверждения)
- [ ] 4.4 Исключить автоматическое утверждение по истечении срока (верификация: тест с истёкшим сроком не отправляет ни инвайт, ни напоминания и уведомляет оператора)
- [ ] 4.5 Реализовать фиксацию решения отдельно по каждому сообщению плана — по инвайту и по каждому напоминанию (верификация: запрос журнала по отдельному напоминанию возвращает его собственное решение, а не ссылку на план)

## 5. Календарь, ICS и ссылка

- [ ] 5.1 Реализовать создание события во внутреннем календаре контура клиента при исполнении утверждённого плана (верификация: после исполнения событие существует в календаре контура клиента и содержит время и ссылку)
- [ ] 5.2 Реализовать генерацию ICS-вложения к письму-инвайту (верификация: тест разбора вложения даёт время и ссылку, совпадающие со внутренним событием)
- [ ] 5.3 Реализовать адаптер генерации ссылки с контрактом «без передачи данных участников» и отказом для несовместимого провайдера (верификация: тест провайдера, требующего имя или контакт участника, возвращает отказ)
- [ ] 5.4 Реализовать запись ссылки в три места: внутреннее событие, ICS, карточка сделки (верификация: тест сравнивает три значения и подтверждает совпадение)
- [ ] 5.5 Убедиться в отсутствии обращений к внешним календарям (верификация: проверка зависимостей и исходящих запросов не находит обращений к календарным API третьих лиц)

## 6. Напоминания

- [ ] 6.1 Реализовать расписание напоминаний как часть утверждаемого плана (верификация: тест изменения расписания требует нового утверждения)
- [ ] 6.2 Реализовать идемпотентное исполнение напоминаний по ключу «звонок + шаг расписания» (верификация: повторный запуск обработки не создаёт дубля отправления)
- [ ] 6.3 Реализовать отдельную запись аудита по каждому отправленному напоминанию (верификация: журнал содержит отдельную запись на каждое отправление с указанием утверждённого плана)
- [ ] 6.4 Реализовать блокировку напоминаний при отсутствии утверждения, при отмене и при переносе без нового утверждения (верификация: тесты трёх случаев не отправляют напоминание и фиксируют причину)
- [ ] 6.5 Исключить отправку пропущенных напоминаний задним числом (верификация: тест восстановления после простоя не порождает отправку пропущенного шага)

## 7. Перенос и отмена

- [ ] 7.1 Реализовать перенос до отправки инвайта (верификация: прежний план теряет силу, создаётся новый черновик плана)
- [ ] 7.2 Реализовать перенос после отправки инвайта с приостановкой напоминаний (верификация: черновик уведомления о переносе создан, напоминания не отправляются до нового утверждения)
- [ ] 7.3 Реализовать отмену звонка со снятием неотправленных напоминаний и сохранением причины (верификация: после отмены напоминания не отправляются, дальнейшие переходы недоступны)

## 8. Публичная страница выбора слота

- [ ] 8.1 Реализовать выдачу уникальной ссылки на страницу для конкретного звонка (верификация: ссылка открывает только свой звонок и не позволяет перечислить чужие)
- [ ] 8.2 Реализовать страницу выбора слота с минимальным набором запрашиваемых полей (верификация: страница показывает только слоты этого звонка и не раскрывает иных сведений)
- [ ] 8.3 Реализовать ограничение частоты обращений и защиту от перебора (верификация: превышение порога блокирует обращения и уведомляет оператора)
- [ ] 8.4 Реализовать истечение срока действия ссылки на страницу (верификация: после истечения срока ссылка не открывает страницу)
- [ ] 8.5 Убедиться в отсутствии идентифицирующих данных в журналах платформы при обработке обращений к странице (верификация: аудит журналов не находит персональных данных)

## 9. Границы данных и отчётность

- [ ] 9.1 Обеспечить размещение звонка и участников в красной зоне (верификация: тест классификации относит запись с именем и контактом участника к красной зоне)
- [ ] 9.2 Реализовать обезличенные агрегаты в зелёной зоне: число звонков, доля состоявшихся, конверсия в сделку (верификация: в агрегатах отсутствуют поля, позволяющие идентифицировать физлицо)
- [ ] 9.3 Реализовать раздельный учёт состояний «слот подтверждён» и «подтверждён вне платформы» в отчётности (верификация: отчёт различает оба состояния и не смешивает их в одной метрике)
- [ ] 9.4 Реализовать историю звонка: изменения состояний, источники сведений, авторы ручных изменений, утверждённые планы и факты отправки (верификация: запрос истории возвращает полную последовательность с временем и авторами)

## 10. Интеграционная проверка

- [ ] 10.1 Провести сквозной сценарий: ответ на письмо → выбор слота на странице → утверждение плана → событие, ICS и ссылка → напоминания → фиксация исхода (верификация: журнал утверждений и аудита содержит все необратимые действия)
- [ ] 10.2 Провести сценарий переноса после исполнения плана (верификация: прежние напоминания сняты, новое утверждение запрошено, новое событие и ссылка созданы)
- [ ] 10.3 Проверить, что движок не исполняет исходящих действий в обход очереди утверждений (верификация: прямой вызов API отправки без утверждённого плана не исполняет действие)
- [ ] 10.4 Проверить выполнение требований спеки (верификация: `openspec validate call-orchestration --strict` проходит без ошибок)
