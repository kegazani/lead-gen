## 1. Приём материалов клиента

- [ ] 1.1 Реализовать приём материалов клиента: адрес сайта, текстовое описание бизнеса, сведения о продукте или услуге, документы (верификация: материалы принимаются в каждом из перечисленных видов; отсутствие любого из них, кроме описания, не блокирует приём)
- [ ] 1.2 Реализовать приём и разбор предоставленных документов через `Firecrawl parse` (верификация: коммерческое предложение в поддерживаемом формате разбирается, извлечённые сведения доступны генерации)
- [ ] 1.3 Реализовать проверку достаточности материалов с сообщением о недостающих сведениях и запретом дополнять их самостоятельно (верификация: при нехватке сведений для обязательного блока система сообщает, каких именно, и не заполняет блок вымышленными данными)
- [ ] 1.4 Реализовать работу по одному описанию бизнеса без адреса сайта (верификация: при отсутствии сайта наполнение строится по описанию)

## 2. Сбор сведений с сайта клиента

- [ ] 2.1 Реализовать сбор сведений с сайта клиента средствами движка 3.1 с ограничением глубины обхода (верификация: обход не выходит за заданные границы; границы фиксируются в результате)
- [ ] 2.2 Реализовать исключение персональных данных: сведения о сотрудниках, руководстве и личные контакты не переносятся в наполнение и не сохраняются в контуре генератора (верификация: тестовая страница с составом руководства и личными контактами не даёт персональных данных ни в наполнении, ни в хранилище)
- [ ] 2.3 Реализовать отказ от раздела, требующего авторизации или обхода защиты (верификация: раздел под авторизацией не читается, ограничение зафиксировано)
- [ ] 2.4 Реализовать честную деградацию при недоступности сайта (верификация: при недоступном сайте генерация продолжается на ручных материалах с уведомлением)

## 3. Структура лендинга

- [ ] 3.1 Реализовать построение перечня блоков и их порядка по предоставленным материалам (верификация: перечень построен; состав зависит от материалов, а не задан целиком заранее)
- [ ] 3.2 Реализовать исключение блока, для которого нет подтверждающих сведений, без заполнения его вымышленными данными (верификация: при отсутствии подтверждений блок не создаётся)
- [ ] 3.3 Реализовать показ структуры оператору до генерации текстов (верификация: тексты не генерируются, пока структура не показана и не утверждена)
- [ ] 3.4 Реализовать утверждение структуры оператором как отдельное действие с фиксацией автора и времени (верификация: генерация текстов запускается только после утверждения; запись об утверждении сохранена)

## 4. Тексты наполнения

- [ ] 4.1 Реализовать генерацию текстов блоков через capability `linguistics` с передачей тональности и языка (верификация: тексты формируются в заданных тональности и языке; собственный механизм генерации не создаётся)
- [ ] 4.2 Реализовать запрет на сведения, отсутствующие в материалах клиента: числовые показатели, сроки, гарантии, результаты (верификация: при отсутствии таких сведений в материалах они не появляются в текстах; соответствующие места остаются незаполненными)
- [ ] 4.3 Реализовать обнаружение расхождений между сайтом клиента и предоставленными документами с сообщением оператору без самостоятельного выбора источника (верификация: при расхождении система сообщает о нём и не выбирает источник сама)

## 5. Данные о компании

- [ ] 5.1 Реализовать подстановку реквизитов и контактов компании: наименование, адрес, телефон, общий адрес электронной почты (верификация: указанные в материалах контакты компании присутствуют в наполнении)
- [ ] 5.2 Реализовать исключение личных контактов и имён сотрудников с сообщением об исключении (верификация: личный номер или личный адрес не попадает в наполнение, факт исключения зафиксирован)

## 6. Форма заявки

- [ ] 6.1 Реализовать формирование формы заявки с составом полей, ограниченным минимально необходимым для связи (верификация: состав полей не превышает минимально необходимого)
- [ ] 6.2 Реализовать передачу заявки в приёмник, указанный клиентом (верификация: поданная заявка достигает приёмника клиента)
- [ ] 6.3 Реализовать транзитный приёмник для клиентов без собственного: пересылка заявки без сохранения (верификация: после серии заявок аудит хранилищ и журналов не находит персональных данных заявителей)
- [ ] 6.4 Реализовать поведение при недоступности приёмника: сообщение посетителю без сохранения заявки на стороне платформы (верификация: при недоступном приёмнике заявка не сохраняется у платформы и не выдаётся как принятая)

## 7. Сборка страницы

- [ ] 7.1 Реализовать сборку HTML и CSS без внешних зависимостей, требующих сети (верификация: страница открывается и отображается при отключённом доступе к внешним ресурсам)
- [ ] 7.2 Реализовать корректное отображение на узком экране (верификация: на мобильной ширине нет горизонтальной прокрутки и потери содержимого)
- [ ] 7.3 Реализовать заполнение метаданных страницы: заголовок, описание, язык (верификация: метаданные заполнены и соответствуют содержанию)
- [ ] 7.4 Реализовать применение бренд-комплекта клиента, при его отсутствии — нейтральное оформление (верификация: оформление соответствует заданному комплекту; без комплекта применяется нейтральное)
- [ ] 7.5 Реализовать выдачу результата архивом HTML, CSS и ресурсов, пригодным для размещения на стороннем хостинге (верификация: распакованный архив открывается локально без доработок)

## 8. Проверка на заимствование

- [ ] 8.1 Реализовать сравнение сформированных текстов с материалами клиента и внешними источниками, доступными движку 3.1 (верификация: дословно совпадающий фрагмент обнаруживается)
- [ ] 8.2 Реализовать переформулирование при дословном совпадении с сообщением о замене (верификация: обнаруженный фрагмент переформулирован, факт замены зафиксирован)
- [ ] 8.3 Реализовать исключения: наименование компании, реквизиты и общеупотребительные термины не переформулируются (верификация: совпадение в реквизитах не вызывает замены)

## 9. Версионирование наполнения

- [ ] 9.1 Реализовать сохранение версий наполнения с историей изменений (верификация: после пересборки доступны предыдущие версии с указанием изменений)
- [ ] 9.2 Реализовать возврат к предыдущей версии (верификация: выбранная версия восстанавливается полностью, включая структуру и тексты)

## 10. Интеграционная проверка

- [ ] 10.1 Провести сквозной сценарий: материалы клиента, сбор с сайта, структура, утверждение, тексты, сборка, выдача архива (верификация: сценарий проходит целиком, результат открывается локально)
- [ ] 10.2 Провести проверку границы персональных данных: аудит хранилищ и журналов после полного цикла и серии заявок (верификация: аудит не находит персональных данных ни из материалов клиента, ни из заявок)
- [ ] 10.3 Провести проверку переиспользования: подтвердить, что тексты генерируются через `linguistics`, а сбор — через движок 3.1 (верификация: собственных механизмов генерации текста и сбора в модуле нет)
- [ ] 10.4 Проверить выполнение требований спеки по capability `landing-page-generator` (верификация: `openspec validate landing-page-generator --strict` проходит без ошибок)
