## Context

Мотивация — `proposal.md`. Факты на момент планирования (сверено с диском, 2026-10-09):

- Глобальный `~/.config/opencode/opencode.json`: `model: deepseek/deepseek-v4-pro`, `small_model: deepseek/deepseek-flash`, `default_agent: lead-max`, есть провайдер `qwen-local`. OpenAI отдельно в файле не описан.
- Провайдер OpenAI подключён по OAuth (`opencode auth list` → `OpenAI oauth`).
- Каталог `opencode models openai` содержит `openai/gpt-6-astra`, `openai/gpt-6.1-sol`, `openai/gpt-6-luna` (и `-fast`-варианты). Наличие в каталоге не доказывает доступ.
- `openai/gpt-6-luna` подтверждён живым стримом (со слов пользователя); Astra и Sol — нет.
- Агенты — markdown-файлы с YAML-frontmatter. Текущие модели: `architect`, `coder`, `judge`, `lead`, `lead-max`, `reviewer` → `deepseek/deepseek-v4-pro`; `researcher`, `tester`, `writer`, `voter` → `deepseek/deepseek-flash`. У всех задан `temperature`.
- В репозитории `lead-gen` нет `opencode.json` и `.opencode/` — глобальный конфиг действует без локального переопределения.
- Резервные копии на диске: `~/.config/opencode/opencode.json.bak-20261006-222714`, каталог `~/.config/opencode/agents.bak-20261009`.

## Goals / Non-Goals

**Goals:**

- Закрепить роли за GPT-моделями как глобальный дефолт: Astra — архитектура и план, Sol — координация, Luna — код, ревью, суд, а также вспомогательные роли и `small_model`.
- Заземлить переключение на фактическую доступность: Luna — сразу (доказана), Astra и Sol — только после smoke-test.
- Не выдумывать entitlement и не записывать недоступный ID в глобальный target.

**Non-Goals:**

- Не гарантировать модель в проектах, где есть локальный override.
- Не менять код, домен, `deploy`, контракты репозитория.
- Не переносить `temperature` на reasoning-роли.

## Decisions

### Решение 1. Модель закрепляется во frontmatter агента, а не наследуется

Каждый целевой агент получает явный `model:` в своём `~/.config/opencode/agents/<agent>.md`.

*Почему:* у всех агентов уже стоит явный `model:`; наследование от глобального `model` не сработает, пока pin есть.

*Альтернатива (отклонена):* менять только глобальный `model`. Он влияет лишь на агентов без явного pin, поэтому `lead`/`lead-max`/`architect` и прочие остались бы на DeepSeek.

### Решение 2. Глобальный `model` → `openai/gpt-6.1-sol`

`model` в `opencode.json` — дефолт для агентов без pin. Приводим его к Sol под формулировку «coordinator / default».

*Почему:* после переезда всех ролей на явные pin незакреплённым агентам достаётся разумный координаторский дефолт.

*Альтернатива (отклонена):* оставить `deepseek/deepseek-v4-pro` дефолтом. Тогда новый/неизвестный агент молча шёл бы на DeepSeek вопреки цели.

*Связь с гейтом:* менять `model` на Sol можно только после успешного smoke-test Sol (Решение 5); иначе недоступный ID сломал бы всех незакреплённых агентов.

### Решение 3. У GPT-ролей убирается `temperature`; `variant` задаётся по роли

У OpenAI reasoning-моделей `temperature` не поддерживается (в каталоге моделей `capabilities.temperature = false` у `gpt-6-astra`, `gpt-6.1-sol`, `gpt-6-luna`), поэтому у `architect`, `lead`, `lead-max`, `coder`, `reviewer`, `judge` и у четырёх вспомогательных ролей поле удаляется. `variant` задаётся значением из реально поддерживаемого моделью перечня (`low`/`medium`/`high`): `coder`, `reviewer`, `judge` → `high` (Luna); `architect` → `high` (Astra); `lead`, `lead-max` → `medium` (Sol); `researcher`, `tester`, `writer`, `voter` → `medium` (Luna), с понижением до `low`, если цена reasoning окажется высокой. Встроенные `plan` (Astra, `high`) и `build` (Luna, `high`) задаются в глобальном `agent`-блоке `opencode.json`; `small_model` → `openai/gpt-6-luna`.

*Почему:* иначе запуск GPT-агента упадёт на неподдерживаемом параметре либо параметр будет молча проигнорирован; `variant` задаётся только тем значением, которое модель реально принимает.

### Решение 4. Support-роли и `small_model` → Luna

`researcher`, `tester`, `writer`, `voter` и `small_model` переводятся на `openai/gpt-6-luna`.

*Почему:* пользователь подтвердил переход на ChatGPT и заметил DeepSeek у вспомогательных агентов; целью является единый провайдер GPT-6, а не гибрид с DeepSeek. Support-роли получают `variant: medium` (понижение до `low` при высокой цене reasoning), `small_model` — `openai/gpt-6-luna`.

*Альтернатива (отклонена):* оставить support-роли на `deepseek/deepseek-flash` ради экономии. Противоречит подтверждённой цели и оставляла бы DeepSeek в целевом наборе.

### Решение 5. План-гейт доступности Astra и Sol

Перед записью ID `openai/gpt-6-astra` и `openai/gpt-6.1-sol` — smoke-test живым запуском (`opencode run -m openai/gpt-6-astra ...`, `opencode run -m openai/gpt-6.1-sol ...`).

- Модель отвечает → её ID пишется в соответствующий target.
- Модель не отвечает → ID **не** пишется; соответствующий агент и, при неудаче Sol, глобальный `model` остаются как есть; change фиксируется как **частичный** с точным текстом ошибки.
- `openai/gpt-6-luna` доказан стримом, гейт не требуется (достаточно подтверждающего прогона).

### Решение 6. Приоритет глобального и локального конфига — честная формулировка

Глобальный `~/.config/opencode` — дефолт, который действует только там, где проект не переопределяет модели через свой `opencode.json`/`.opencode`. Локальный конфиг приоритетнее, поэтому результат — не жёсткая гарантия. Формулировка фиксируется в `proposal.md`/`design.md` и в записи `docs/progress-log.md`; JSON-конфиг комментарии не поддерживает, поэтому inline-пометка не ставится.

### Решение 7. Файлы вне репозитория и внешний root

Целевые файлы лежат в `~/.config/opencode`, вне рабочего дерева `lead-gen`. Если инструмент записи ограничен external root и не может править глобальный конфиг, правка не выполняется: глобальный конфиг не трогается, задача остаётся открытой и фиксируется как факт с точным ограничением.

## Risks / Trade-offs

- **[Локальный override перекрывает глобал]** → документируем результат как глобальный дефолт, а не гарантию; проверка идёт на проекте без локального конфига.
- **[Astra/Sol недоступны]** → план-гейт (Решение 5): ID не пишется, change частичный, ошибка фиксируется.
- **[Sol недоступен при смене глобального `model`]** → оставить `model` прежним, не ломать незакреплённых агентов; пометить change частичным.
- **[Reasoning-модель отвергает `temperature`]** → удалить поле у GPT-ролей; проверка живым запуском агента.
- **[Глобальная смена влияет на другие проекты пользователя]** → это и есть цель; откат из бэкапов возвращает прежнее поведение.
- **[Откат]** → `~/.config/opencode/opencode.json.bak-20261006-222714` и `~/.config/opencode/agents.bak-20261009`.

## Migration Plan

1. Сверить целевые файлы и бэкапы, зафиксировать исходные frontmatter и `opencode.json`.
2. План-гейт: smoke-test Astra, Sol, Luna; зафиксировать матрицу доступности.
3. Для прошедших моделей применить per-agent frontmatter и удалить `temperature` у GPT-ролей.
4. Применить глобальный `model` (только если Sol прошёл).
5. Проверить `opencode models` и живой запуск затронутых агентов.
6. Откат: восстановить `opencode.json` и `agents/` из бэкапов.

## Open Questions

- Точный entitlement Astra/Sol определяется smoke-test, а не design; до прогона это неизвестно и на состав задач не влияет.
- Нужно ли позже понижать `variant` support-ролей до `low` из-за цены reasoning — решается после первых прогонов, в этом change только переключение модели.
- Нужно ли дублировать глобальные настройки в проектном `lead-gen` (сейчас конфига нет) — вне scope.
