## Context

Операторская консоль проектируется change `web-frontend-architecture` (HTMX + `html/template`, эксплуатационная проекция роли `api`). Клиентского контура нет. Модель тенантов — `platform-access` (`platform-governance`); заявка — агрегат `request` (`request-fulfillment`, change №1). Мотивация — в `proposal.md`.

## Goals / Non-Goals

**Goals:**

- Определить портал как эксплуатационную проекцию без новой доменной модели.
- Связать регистрацию с `platform-access`, подачу заявки — с `request-fulfillment`.
- Задать маскирование: клиент видит только агрегаты/метрики.

**Non-Goals:**

- Метрики и графики дашборда — change №6.
- Сама форма валидации (админ) — change №3.
- Дизайн-система/брендбук.

## Decisions

### Решение 1: портал — эксплуатационная проекция, не bounded context

`client-portal` не владеет агрегатами и не вводит доменных событий/политик — по образцу `console-appearance`/`lead-cards-console`. Владелец capability — `platform-governance` (поверхность доступа клиента).

### Решение 2: регистрация — self-service через `platform-access`

Регистрация создаёт тенант и пользователя с ролью клиента, переиспользуя модель `platform-access`. `access-decision` применяется как обычно; новая RBAC-семантика не вводится.

### Решение 3: подача заявки — контракт `request-fulfillment`

Форма оффера вызывает команду создания заявки в `request-fulfillment` через синхронный `command`-контракт. Портал не пишет в хранилище заявок напрямую.

### Решение 4: маскирование на сервере

Клиенту отдаются только агрегаты и метрики. Сырые лиды, контакты и статусы краулинга не покидают сервер. Портальный read-путь — только через агрегированные проекции.

## Risks / Trade-offs

- **[Утечка PII клиенту]** → Маскирование на сервере (Решение 4) + проверка на ревью, что клиентские эндпоинты не возвращают сырых записей.
- **[Регистрация обходит правила доступа]** → Регистрация идёт через `platform-access`/`access-decision`, отдельный путь доступа не создаётся.
- **[Портал тянет данные нескольких контекстов]** → Сборка через контракты (`sync`/`http-json`), а не прямой доступ к чужим хранилищам.

## Migration Plan

Нового хранилища нет: портал — проекция. Развернуть экраны регистрации и формы заявки, подключить контракты. Откат: экраны изолированы, существующие операторские потоки не затрагиваются.
