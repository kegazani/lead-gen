## Why

Сейчас оператор не может задать, **сколько компаний** должно найти задание поиска, и не может **вручную** вписать цели обхода: цели выводит LLM из текста запроса, а панель плана на экране ассистента доступна только для чтения. Обход при этом жёстко ограничен глубиной, временем и внутренним предохранителем страниц, поэтому задание останавливается по исчерпании небольшого запаса целей, а не по достижению нужного объёма. Оператору нужен режим «искать, пока не наберётся N компаний», с ручным управлением целями, лимitом поиска и опциональным кредитным предохранителем.

## What Changes

- Новый параметр задания — **целевое число компаний** (`targetCompanies`): задание завершается `done`, когда найдено не меньше N уникальных компаний. Значение `0` сохраняет текущее поведение (цель не задана).
- **Добор целей (вариант B):** когда цели плана исчерпаны, а целевое число не достигнуто, задание добирает новые цели (через LLM и/или расширение поиска) и продолжает работу. Остановка добора — при достижении N, исчерпании бюджета, отсутствии прироста целей или отмене оператором.
- **Цели вручную:** оператор может вписать seed-цели (поисковые запросы и/или стартовые URL) в форме запуска и править черновик плана ассистента. Ручные цели используются дословно, добор добавляется к ним.
- **Ручной лимит поиска** (`maxResults` — число результатов на один поисковый запрос) как операторский параметр формы.
- **Снятие обязательных лимитов обхода:** глубина и время обхода перестают быть обязательными; обход может идти без заданных глубины, времени и внутреннего предохранителя страниц. **BREAKING** для требования «обход только по явному лимиту»: единственным денежным тормозом остаётся опциональный кредитный бюджет.
- **Опциональный кредитный бюджет** сохраняется как дополнительная страховка расхода; он не задаётся по умолчанию.
- Панель плана на экране ассистента становится **редактируемой**; форма «Новый поиск» на главной получает поля целевого числа компаний, лимита поиска и ручных целей.
- Прогресс задания показывает **«найдено X из N»** и текущую итерацию добора целей.

## Capabilities

### New Capabilities
- `company-quota-search`: поиск до заданного целевого числа уникальных компаний с автоматическим добором целей и определёнными условиями остановки задания.

### Modified Capabilities
- `search-strategy`: план согласуется и правится вручную (seed-цели), вводятся операторские `targetCompanies` и `maxResults`; панель плана редактируема; снимается запрет спрашивать число целей.
- `search-job-progress`: прогресс отражает целевое число компаний, отношение «найдено X из N» и итерацию добора целей.
- `firecrawl-credit-budget`: обход перестаёт требовать обязательных глубины, времени и внутреннего предохранителя страниц; кредитный бюджет остаётся опциональным денежным тормозом.

## Impact

**Затрагиваемые bounded contexts:**
- `lead-management` — прикладной слой `RunSearch` (петля добора целей, условие остановки по числу компаний, снятие требования глубины/времени), порты (`SearchJobPayload`: `targetCompanies`, `maxResults`), HTTP-адаптер и шаблоны (`dashboard.html`, `assistant.html`), представления форм.
- `integration-platform` — адаптер `firecrawl` и бюджетная обёртка `guard` (обход без обязательного `max_pages`/глубины/времени, поиск с операторским `maxResults`).

**Доменная модель:** новых агрегатов и domain events не появляется; изменение ограничено расширением wire-формата задания поиска и поведения обхода. Поскольку вводится новая capability `company-quota-search`, она регистрируется у владельца `lead-management` в `architecture/domain-catalog.yaml` и в capability matrix в `docs/domain-model.md`; сами диаграммы не меняются (состав контекстов и связей тот же).

**Команды и данные:** изменение `SearchJobPayload` обратно совместимо (старые задания без новых полей читаются как «цель не задана», «лимит по умолчанию»). Изменение снятия лимитов обхода требует правки требования `firecrawl-credit-budget` и несовместимо с прежним гарантированным контролем расхода по страницам — риск фиксируется в design.
