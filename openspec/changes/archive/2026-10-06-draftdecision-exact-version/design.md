## Context

Мотивация — `proposal.md` (Why). Требование — дельта `outreach-approval` (ADDED:
«Решение читается только по запрошенной версии черновика»).

Текущее состояние, задающее рамку:

- Read-контракт `draftdecision` (`contracts/outreach-orchestration/draftdecision`)
  адресует решение парой «непрозрачная ссылка на черновик + точная версия»
  (`Lookup{TenantID, DraftRef, DraftVersion}`) и объявляет исходы
  `ErrNotFound`/`ErrPending`/`ErrRejected`/`ErrUnavailable`. Его документация уже
  фиксирует: «запрос версии, не совпадающей с текущей, не выдаёт старое решение за
  действующее».
- Владелец реализует контракт в `backend/contexts/outreach-orchestration`:
  `Service.ApprovedAction` (`agent_approval_port.go`) → `query.ApprovedActionHandler.Handle`
  (`internal/app/query/approved_action.go`). HTTP-поверхность —
  `GET /approved-action` (`handlers_approved_action.go`).
- Агрегат `campaign` хранит черновики (`ActionDraft`, поле `version`, инкремент при
  доработке `ReviseDraft`) и решения (`OperatorDecision`, неизменяемые, привязаны к
  точной версии черновика — инвариант I2). `Campaign.DecisionsForDraft(id)` —
  выборка решений по черновику.
- Потребитель `draftdecision` — шаг `send` агента (`agent-orchestration`); его
  адаптер (`backend/cmd/lead-gen/agent_approval_contracts.go`) отображает
  `ErrPending` и `ErrNotFound` в `ErrApprovedActionPending`, `ErrRejected` — в
  `ErrApprovedActionRejected`, прочее — в `ErrApprovedActionUnavailable`.

**Первопричина дефекта.** `Handle` вызывал `currentDecision(campaign, draft)`,
который сравнивал версию решения с **текущей** версией черновика
(`decision.DraftVersion() == draft.Version()`), а не с запрошенной `q.DraftVersion`.
Запрошенная версия в выборе решения не участвовала: при доработке черновика и
решении по новой версии запрос по старой версии получал решение новой.

## Goals / Non-Goals

**Goals:**

- Решение выдаётся строго для запрошенной версии; запрос устаревшей/неизвестной
  версии не выдаёт решение другой версии.
- Исходы чтения различимы и честны: несовпадение/отсутствие, ожидание, отклонение,
  недоступность не смешиваются.
- Исправление не меняет наблюдаемого поведения потребителя `agent-orchestration`.

**Non-Goals:**

- Не вводятся новые исходы контракта: потребитель (`backend/cmd/lead-gen/**`) в
  этой зоне неизменяем, а неизвестный исход он трактует как недоступность — новый
  исход превратил бы «не санкционировано» в «источник недоступен».
- Не меняется публикуемая форма `draftdecision`/`approved-action` и публикация
  события: правится только выбор решения при чтении.
- Не меняется доменная модель, каталог границ, агрегаты и связи.
- Не меняется HTTP-поверхность и перевод исходов: они уже несут нужные ветви.

## Decisions

### Решение 1. Анкер — запрошенная версия, а не текущая

`Handle` SHALL считать решение действующим только если `q.DraftVersion` совпадает с
текущей версией черновика (`draft.Version()`), и лишь затем искать решение **по
этой** версии. Сравнение с текущей версией, а не только с версией решения,
необходимо: решение по запрошенной версии, уже превзойдённой доработкой, —
устаревшее и не санкционирует отправку (инвариант I2).

**Альтернатива.** Искать решение только по `q.DraftVersion`, не сверяя с текущей
версией, — отвергнута: тогда запрос устаревшей версии вернул бы её (пусть и старое)
решение, то есть выдал бы санкцию по версии, которая уже не действует. Именно это
запрещает инвариант «изменённый черновик требует нового решения».

**Форма.** Из `Handle` убирается скрытая зависимость от `draft.Version()`; выбор
решения вынесен в `decisionForVersion(campaign, draftID, version)`, сравнивающий с
`q.DraftVersion`.

### Решение 2. Отображение исходов: несовпадение — «не найдено»

Запрошенная версия не совпадает с текущей либо решения по ней нет →
`ErrDraftDecisionNotFound`. Это эксплицитно покрыто документацией контракта
(`ErrNotFound`: «запрошена версия, к которой действующего решения нет») и не
выдаётся за ожидание: «решение не принято» относится к текущей версии черновика в
ожидании, а несовпавшая версия — это отсутствие действующего решения по запросу.
Отклонение по точной (текущей) версии → `ErrDraftDecisionRejected`; ожидание по
текущей версии → `ErrDraftDecisionPending`; недоступность хранилища → проброс как
есть (на границе контракта — `ErrUnavailable`).

**Почему не новый исход.** Потребитель вне зоны правки отображает неизвестную
ошибку в недоступность; новый исход исказил бы смысл. Существующий `ErrNotFound`
уже различим и безопасен для потребителя (он трактует его как «ещё не
санкционировано» — отправка не выполняется).

### Решение 3. Совместимость потребителя

Шаг `send` (`agent-orchestration`) отображает `ErrPending` и `ErrNotFound` в один
исход `ErrApprovedActionPending`, поэтому исправление не меняет его наблюдаемого
поведения: и до, и после запрос неактуальной версии не приводит к отправке. Меняется
только корректность ответа владельца: раньше при определённых состояниях он отдавал
решение не той версии (что потребитель мог принять за санкцию), теперь — явный
исход. Правки `backend/cmd/lead-gen/**` не требуются.

## Risks / Trade-offs

- [Потребитель полагался на «решение текущей версии» при запросе устаревшей] →
  такое поведение не санкционировано ни спекой, ни контрактом; потребитель
  безопасно отображает `ErrNotFound` в «не санкционировано».
- [Изменение исхода для устаревшей версии с `ErrPending` на `ErrNotFound`] → на
  потребителе оба исхода эквивалентны; для владельца `ErrNotFound` точнее и
  соответствует документации контракта.
- [Расширение исходов контракта] → отвергнуто (Решение 2): новых исходов нет.

## Migration Plan

1. Исправить `query.ApprovedAction.Handle`: анкер на `q.DraftVersion`, явные исходы;
   вынести выбор решения в `decisionForVersion`.
2. Обновить/добавить тесты `internal/app/query/approved_action_test.go`: точная
   версия, устаревшая версия после доработки (в т.ч. при решении по новой версии),
   неизвестная версия, ожидание, отсутствие, отклонение, доступ/тенант; недоступность
   источника на границе контракта.
3. Гейт: `go test ./... && go vet ./...` и `go test ./...` в
   `contracts/outreach-orchestration`; `go -C tools/importlint run .` — 0;
   `go -C tools/archlint run .` — код 0; `openspec validate draftdecision-exact-version --strict` — valid.

Откат не требуется: изменение — исправление выбора решения; прежние некорректные
ответы не являются контрактными обязательствами.
