## Why

Живой прогон (клиент → заявка → админ → одобрение) показал: авто-генерация писем
не запускается из UI. Workflow `Fulfillment` генерирует черновики только при
наблюдаемом **недоборе** (`shortfall > 0`), а недобор считается лишь при **явной
цели по числу лидов** (`explicitTarget`). Штатный UI-путь одобрения заявки
(`handleValidationApprove` → `startFulfillment`) стартует исполнение с жёстко
зашитым `LeadTarget: 0`, поэтому цель не задана, недобор не рассчитывается, и шаг
писем не срабатывает. У администратора нет способа задать цель из UI.

## What Changes

- На экране валидации/одобрения заявки (форма одобрения) появляется
  необязательное числовое поле «Цель по числу лидов».
- Значение поля пробрасывается в запуск исполнения
  (`ports.StartFulfillment.LeadTarget`) вместо захардкоженного `0`.
- Пустое значение (и `0`) означает «цель не задана» — прежнее поведение
  сохраняется (обратная совместимость).
- Отрицательное (и нецелое) значение отклоняется понятной ошибкой `400` до
  применения одобрения: исполнение не запускается, заявка не переводится в
  `validated`.
- API-путь `POST /requests/{id}/start-workflow` получает такую же проверку
  отрицательной цели для согласованности с экраном.
- **Не входит:** сохранение числовой цели в агрегате заявки, согласование
  свободного текста цели (`request-target`) с числом, изменение графа workflow,
  контрактов `email-generation`/`vector`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `request-validation`: при одобрении валидатор может задать необязательную
  числовую цель по числу лидов; пусто/`0` — цель не задана (прежнее поведение),
  отрицательное значение отклоняется с понятной причиной.

## Impact

**Affected bounded contexts:** `request-fulfillment` (владелец `request-validation`
и экрана одобрения). Внешние контракты не меняются: цель — существующее поле
`ports.StartFulfillment.LeadTarget`, workflow и контракт `email-generation` уже
готовы принимать недобор.

**Доменная модель.** Не меняется. Числовая цель остаётся параметром запуска
исполнения, а не полем агрегата `request`: change не добавляет сущностей,
событий, связей и не меняет владение. `architecture/domain-catalog.yaml`,
`docs/domain-model.md` и диаграммы не затрагиваются.

**Код.** `backend/contexts/request-fulfillment/internal/adapters/http`
(`validation_screen.go`, шаблон `validation_screen.html`, `handlers.go`,
`messages.go`), тесты пакета. Контракты `contracts/request-fulfillment` не
требуют изменений.
