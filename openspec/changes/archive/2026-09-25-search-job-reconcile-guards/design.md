## Context

См. `proposal.md` — мотивацию. Уже реализовано отдельным change: охраняемые переходы `jobs.Store.UpdateStatus(ctx, id, from, to, …)`, решительная отмена (`RequestCancel` для `running` сразу даёт `cancelled`), распознавание отмены по данным (`FindByID` + наблюдатель в `Runner.RunOnce`) и согласование осиротевших заданий `ReconcileRunning(ctx)`, вызываемое в `Service.runWorker` перед первым взятием задания. Здесь меняется только согласование: оно получает аренду и лимит попыток.

- Аренда опирается на `UpdatedAt`: запись прогресса и любые переходы обновляют его, поэтому свежая активность означает живое задание.
- `Attempts` увеличивается при каждом `TakeQueued` и сохраняется при согласовании — на нём строится лимит.
- Коды отказа определяет прикладной слой (`internal/app`), примитив `jobs` их значений не знает.

## Goals / Non-Goals

**Goals:**

- Не выдавать задание второму обработчику, пока его выполняет живая копия.
- Не возвращать в очередь бесконечно задание, падающее на каждом запуске: после лимита — отказ с отдельным кодом.
- Не ломать уже реализованные решительную отмену и распознавание отмены по данным.

**Non-Goals:**

- Не менять охраняемые переходы, решительную отмену и наблюдатель отмены.
- Не вводить распределённую блокировку: аренда остаётся эвристикой по времени активности.
- Не менять схему данных.

## Decisions

### D1. Аренда по времени активности

Согласуются только задания, у которых `UpdatedAt` старше срока аренды. Альтернатива без аренды (как сейчас) отбирает задание у живой копии при старте второй; отклонена.

### D2. Лимит попыток и код прерывания

Если у осиротевшего задания `Attempts >= MaxAttempts`, оно переходит в `failed` с кодом `lifecycle.interrupted` и бизнес-формулировкой; иначе возвращается в очередь. Порядок проверок: сначала признак запроса отмены (`cancelled`), затем лимит попыток, затем возврат в очередь.

### D3. Расширение контракта согласования

`jobs.Store.ReconcileRunning` получает параметры: срок аренды (`staleBefore`), лимит попыток и — непрозрачными строками — код и формулировку отказа для исчерпания попыток. Возвращает счётчики исходов (возвращено, отменено, провалено) для наблюдаемости вместо одного числа. Значения кода примитив не знает — их определяет прикладной слой.

Альтернатива — оставить сигнатуру и зашить политику в хранилище — отклонена: политика (срок аренды, лимит, код) задаётся прикладным слоем и должна быть настраиваемой.

### D4. Раннер передаёт политику

`Runner` получает поля `LeaseTTL`, `MaxAttempts`, `FailCode`, `FailReason` со значениями по умолчанию; `Runner.Reconcile` подставляет их в вызов хранилища.

### D5. Код прерывания в прикладном слое

В перечне кодов `app` появляется `ErrorCodeInterrupted = "lifecycle.interrupted"` с формулировкой (например, «Задание прервано перезапуском»). Формулировка становится доступной извне пакета, чтобы `service.go` передал её в раннер.

### D6. Значения по умолчанию

Срок аренды по умолчанию — заведомо больше интервала обновления прогресса; лимит попыток по умолчанию — небольшая величина, дающая одну повторную попытку. Оба значения настраиваются через конфигурацию сервиса.

## Risks / Trade-offs

- [Аренда с запасом может надолго задержать восстановление задания, чей прогресс обновляется редко] → срок аренды задаётся с запасом относительно наблюдаемого интервала обновления.
- [Осиротевшее задание с исчерпанными попытками помечается `failed`, хотя оператор его не запускал повторно] → отдельный код `lifecycle.interrupted` и понятная формулировка отличают это от отказа движка.
- [Изменение сигнатуры `ReconcileRunning` затрагивает оба хранилища и вызов в `service.go`] → изменение локально и покрывается контрактными тестами обоих адаптеров.

## Migration Plan

- Схема данных не меняется, миграций нет.
- Развёртывание: обновлённый образ роли worker.
- Откат: возврат кода; накопленные `running`-задания при следующем старте снова согласуются по прежней (без аренды) логике.

## Open Questions

- Конкретные значения срока аренды и лимита попыток по умолчанию (D6) — настраиваемые величины, подбираются без изменения спецификации.
