## Context

Мотивация — `proposal.md`. Порт эмбеддингов и его проводка уже реализованы
(`embedding-config-separation`): `vectorRecallPort`
(`backend/cmd/lead-gen/runners.go`) собирает OpenAI-совместимый эмбеддер
(`integration-platform/internal/adapters/openai`) и персистентный store
(`integration-platform/internal/adapters/vector/postgres`) при непустом
`-embedding-key`. Не хватало конкретного провайдера. Задача — выбрать
self-hosted движок и многоязычную модель и провести их в контур.

## Decisions

### Решение 1. Движок — self-hosted Ollama, а не Hugging Face TEI

**Выбор.** Сервис `embeddings` в `compose.yaml` на образе `ollama/ollama`,
модель `bge-m3`.

**Почему.** Хост разработки — macOS **arm64**. Образы Hugging Face
text-embeddings-inference (`cpu-*`) публикуются только под `linux/amd64` и
требуют AVX; на arm64 они исполнялись бы через эмуляцию и могли бы не
запуститься. Ollama публикует нативные `arm64`-образы и работает на Docker
Desktop для macOS без эмуляции. Оба варианта дают OpenAI-совместимый
`POST /v1/embeddings` и не требуют внешнего ключа; выбор продиктован
запускаемостью на целевом хосте.

### Решение 2. Модель — `bge-m3` (многоязычная)

**Выбор.** `bge-m3` (1024 измерения, многоязычная).

**Почему.** Запросы и тексты на русском; нужна многоязычная модель, а не
англоцентричная (`nomic-embed-text`). `bge-m3` — средний размер, приемлемая
скорость на CPU для коротких текстов. Векторный store хранит
`double precision[]` без фиксированной размерности
(`integration-platform/migrations/0002_vector_index.sql`), поэтому 1024
измерения принимаются без изменений схемы. E5-префиксы (`query:`/`passage:`)
не используются: адаптер шлёт сырой текст — допустимо для recall-кандидатства.

### Решение 3. `EMBEDDING_BASE_URL` — базовый адрес без суффикса `/v1`

**Выбор.** `EMBEDDING_BASE_URL=http://embeddings:11434` (внутри сети compose).

**Почему.** Клиент склеивает адрес и путь конкатенацией:
`endpoint("/v1/embeddings") = baseURL + "/v1/embeddings"` (`openai.go`). Если
базовый адрес уже содержит `/v1` (`https://api.openai.com/v1`), получится
`/v1/v1/embeddings` — ошибка. Поэтому базовый адрес задаётся без `/v1`. В
`.env.example` это отмечено явно; прежний пример `https://api.openai.com/v1`
исправлен на `https://api.openai.com`.

### Решение 4. `EMBEDDING_KEY=local` — фиктивные креды, не заглушка функции

**Выбор.** Для локального сервера без авторизации задаётся непустое значение
`EMBEDDING_KEY=local`.

**Почему.** `NewEmbedder` требует непустой ключ, чтобы продуктовый путь не
подменялся детерминированным двойником молча. Ollama не проверяет
`Authorization`, поэтому значение фиктивно, но **не является заглушкой
функции** (`AGENTS.md` §3): реальный эмбеддинг выполняется настоящим движком,
отказ при недоступности остаётся честным. Это тот же приём, что
`Authorization: Bearer <key>` к серверу, который его игнорирует.

### Решение 5. Локальный провайдер по умолчанию, внешний — опция

**Выбор.** В `x-app-command` значения по умолчанию —
`${EMBEDDING_BASE_URL:-http://embeddings:11434}`,
`${EMBEDDING_MODEL:-bge-m3}`, `${EMBEDDING_KEY:-local}`. Переопределение `.env`
переключает на внешний OpenAI-совместимый провайдер.

**Почему.** Контур должен работать «из коробки» без внешнего ключа. Пустое
значение `EMBEDDING_KEY` (как раньше) оставляет recall честно недоступным —
это сохраняется как откат.

### Решение 6. Без правок кода

**Выбор.** Изменения только в `compose.yaml`, `.env.example`, `deploy/README.md`.

**Почему.** Адаптер и проводка `EMBEDDING_*` уже есть. Кода на Go правка не
требует; изменение инфраструктурное.

## Risks / Trade-offs

- **[Модель не скачана]** → сервис `embeddings` на старте сам выполняет
  `ollama pull`; до готовности модели запрос recall вернёт честную ошибку
  провайдера, а не выдуманный вектор.
- **[Первый запуск качает образ и модель]** → разовая сетевая операция (Docker
  Hub / реестр Ollama); далее — том `ollama-models`, переживает рестарт.
- **[CPU-инференс]** → для коротких текстов приемлемо; выбор модели среднего
  размера ограничивает задержку.
- **[Расхождение размерности]** → хранилище размерность не фиксирует, так что
  смена модели не ломает схему.

## Migration Plan

1. Добавить сервис `embeddings` в `compose.yaml` (образ, healthcheck, том,
   авто-`pull` модели).
2. Задать дефолты `EMBEDDING_*` в `x-app-command`, указывающие на `embeddings`.
3. Обновить `.env.example` (локальный провайдер по умолчанию, оговорка про
   `/v1`) и `deploy/README.md`.
4. Приёмка: `docker compose up -d`, проверка health `embeddings` и вектора на
   `POST /v1/embeddings`; затем живой recall в контуре и строки в
   `"integration-platform".vector_document`.

**Откат.** Пустой `EMBEDDING_KEY` (или удаление сервиса `embeddings`) =
прежнее поведение «вектор недоступен».
