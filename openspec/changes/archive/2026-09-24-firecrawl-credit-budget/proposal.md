## Why

Срез `mvp-lead-search` подключает Firecrawl (hosted API) без защиты расхода: адаптер вызывает `/search`, `/crawl` и `/scrape` напрямую, не проверяя кредитный баланс, не ограничивая частоту и параллелизм, и не закладывая бюджет на задачу. На бесплатном плане это риск: обход с `limit` по умолчанию (10 000 страниц), ретраи 429 без паузы и отсутствие жёсткого потолка могут выжечь кредиты аккаунта за одну задачу. Нужен модуль безопасного использования Firecrawl, который управляет только расходом Firecrawl в кредитах и делает невозможным превышение заданного бюджета задачи.

## What Changes

- **Вводится capability `firecrawl-credit-budget`** (контекст `integration-platform`): кредитный бюджет на одну задачу, подтверждённый остаток аккаунта, предохранители частоты/параллелизма/размера обхода и обработка ошибок 429/402.
- **Бюджет задачи.** Пользователь задаёт `max_credits` — жёсткий лимит кредитов Firecrawl на задачу. Для задачи хранятся `max_credits`, `reserved_credits`, `confirmed_spent_credits`, статус, параметры запросов и идентификаторы запущенных crawl-заданий. Резервирование бюджета атомарно для всех воркеров: два параллельных запроса не могут получить разрешение потратить одни и те же оставшиеся кредиты.
- **Остаток аккаунта.** Перед задачей запрашивается `GET /v2/team/credit-usage`; показывается `data.remainingCredits` как «Остаток кредитов Firecrawl» вместе со временем последнего успешного обновления. `planCredits` за текущий остаток не выдаётся. При ошибке показывается «Остаток недоступен», вычисленное значение не подставляется.
- **Токены Firecrawl — только информационно.** `GET /v2/team/token-usage` вызывается только для необязательного поля «Токены Firecrawl: …»; поле показывается лишь при успешном ответе с `data.remainingTokens`, при ошибке скрывается. Токены не используются как единица стоимости `scrape`/`search`/`crawl`.
- **Предохранители запросов.** Один общий лимитер на аккаунт: не более одного затратного запроса одновременно, пауза не менее 10 секунд между обычными запросами и не менее 40 секунд между запусками `crawl` (значения в конфигурации, начальные строже документированных лимитов Free-плана).
- **Обход по бюджету.** Для `crawl` вычисляется максимальное число страниц из доступного бюджета и передаётся явным `limit`; без явно заданного небольшого `limit` обход не запускается. После завершения фактический расход сверяется, неиспользованный резерв освобождается.
- **Обработка ошибок.** HTTP 429 — пауза очереди и повтор с возрастающей задержкой и случайным разбросом, число повторов ограничено. HTTP 402 — остановка новых затратных запросов с причиной пользователю. `metadata.statusCode` 403/404 в результате не приводит к бесконечному повтору того же URL.
- **Обычный markdown, без опций с доп. стоимостью.** В первой версии используется обычный markdown; опции с дополнительной стоимостью (извлечение JSON) не включаются, а при появлении их стоимость должна учитываться в проверке бюджета до выполнения.

## Capabilities

### New Capabilities

- `firecrawl-credit-budget`: управление расходом кредитов Firecrawl на задачу — бюджет задачи с атомарным резервированием, подтверждённый остаток аккаунта, информационное поле токенов, предохранители частоты/параллелизма/размера обхода и обработка ошибок 429/402.

### Modified Capabilities

Нет.

**Обоснование.** Существующие capability (`provider-agnostic-integrations`, `osint-enrichment`) описывают изоляцию от поставщика и сбор данных; управление кредитным расходом конкретного платного движка — отдельное поведение, видимое оператору (лимит, остаток, доступный бюджет), и потому оформляется новой capability. Доменные агрегаты каталога не меняются: бюджет задачи — операционная запись прикладного слоя адаптера, а не новая сущность каталога.

## Impact

- **Affected bounded contexts:** первичный — `integration-platform` (адаптер Firecrawl и новая capability `firecrawl-credit-budget`); потребитель — `lead-management` (поисковое задание создаёт бюджет задачи и вызывает Firecrawl только через него). Каталог: `firecrawl-credit-budget` добавляется в список capability контекста `integration-platform`.
- **Доменная модель не затрагивается:** агрегаты, события, политики и связи каталога остаются без изменений; бюджет задачи — операционная запись, а не агрегат.
- **Код:** новые файлы в `backend/contexts/integration-platform/internal/adapters/firecrawl` (модель стоимости, бюджет с атомарным резервированием, клиент `credit-usage`/`token-usage`, лимитер, обёртка с бюджетом и обработкой ошибок); новый контракт `contracts/integration-platform/budget`; впрыск в `backend/cmd/lead-gen`; минимальная правка `backend/contexts/lead-management` для создания бюджета на задание.
- **Зависимости:** без новых внешних зависимостей — только стандартная библиотека Go (HTTP-клиент Firecrawl уже на stdlib).
- **Проверка:** unit-тесты всех инвариантов (атомарное резервирование, обход по бюджету, недоступный остаток, скрытие токенов, backoff 429 и остановка 402, освобождение резерва); `make check` и `go -C tools/archlint run .` зелёные.
