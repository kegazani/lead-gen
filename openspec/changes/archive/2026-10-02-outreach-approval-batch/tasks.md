## 1. Доменный слой: состав пакета и однородность

- [x] 1.1 Реализовать на aggregate root `campaign` метод `BuildApprovalBatch` с ключом однородности (**материал + сегмент, точные версии**) и лимитами пакета, переданными параметром (верификация: тест группирует однородные черновики в один состав и не объединяет различающиеся материалом или сегментом; при превышении лимита возвращается несколько шардов)
- [x] 1.2 Реализовать в `BuildApprovalBatch` проверку минимального размера: состав меньше минимального числа для пакета не формируется (верификация: тест направляет такие черновики на индивидуальное рассмотрение, пакет не создаётся)
- [x] 1.3 Реализовать в агрегате исключение черновиков с признаком риска: обнаруженные персональные данные, непроверенный адрес, отсутствие обязательных сведений, сработавшее правило остановки (верификация: тест по каждому признаку исключает черновик из состава)
- [x] 1.4 Реализовать возврат исключённых черновиков с причинами вместо молчаливого отбрасывания (верификация: тест проверяет, что результат содержит исключённые черновики и причину по каждому; исключение нельзя обойти — повторная попытка включить рисковый черновик в состав отвергается)

## 2. Доменный слой: пакетное решение

- [x] 2.1 Реализовать на aggregate root `ApproveBatch`: создание **N отдельных `operator-decision`** по каждому черновику с автором, временем, результатом и привязкой к точной версии черновика (верификация: тест на N черновиков получает N записей решений; записи на пакет целиком нет)
- [x] 2.2 Добавить в `operator-decision` признак пакетного принятия (провенанс пакета) без изменения формы одиночного решения (верификация: признак сохранён и отличим при аудите; одиночное решение признака не несёт)
- [x] 2.3 Реализовать повторную валидацию состава при принятии решения и проверку digest состава (верификация: решение с несовпадающим digest или с изменившимся составом отвергается без изменения состояния; I2 сохранён)
- [x] 2.4 Реализовать сохранение идемпотентности по паре (`draft_id`, `draft_version`) для пакетного пути (верификация: повтор той же пакетной команды не создаёт вторую запись решения и не меняет состояние)
- [x] 2.5 Эмитировать N × `action-approved` (с точной версией черновика в payload) и `campaign-state-changed`; новых domain events не вводить (верификация: тест утверждения пакета получает ровно N событий `action-approved` и событие `campaign-state-changed`; событие «пакет утверждён» отсутствует)
- [x] 2.6 Реализовать отклонение внутри пакета как обычный `RejectDraft` с причиной и возвратом на доработку (верификация: отклонённый черновик из пакета помечен причиной, не исполняется и требует нового решения после доработки)
- [x] 2.7 Убедиться, что инварианты I1 и I2 не ослаблены (верификация: тест подтверждает — действие не переводится в исполнение без положительного решения для точной версии, изменённый после состава черновик требует нового решения)

## 3. Прикладной слой

- [x] 3.1 Реализовать use case формирования пакета: загрузка окна, вызов `BuildApprovalBatch`, возврат состава, числа исключённых и причин (верификация: тест получает состав с числом черновиков, основанием однородности, образцом содержимого и перечнем отличий внутри пакета)
- [x] 3.2 Реализовать вычисление и возврат digest состава вместе с составом (верификация: digest детерминирован для одного состава и различается при изменении набора или версий черновиков)
- [x] 3.3 Реализовать use case `ApproveBatch` по digest: без digest или при несовпадении решение не принимается (верификация: сценарий «Решение без просмотра» — утверждение без полученного состава отвергается; с полученным digest проходит)
- [x] 3.4 Реализовать query пакетной проекции очереди по ключу однородности (верификация: проекция строится из результата агрегата, а не своей фильтрацией; query не решает, кого исключать)
- [x] 3.5 Реализовать запрос журнала решений по черновику с возвратом его собственного решения и признака пакетного принятия (верификация: журнал по черновику не возвращает ссылку на пакет; пакетное решение отличимо от одиночного)
