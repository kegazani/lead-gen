# Задачи: self-hosted краулер (Crawl4AI + прокси-пул)

## 1. Каталог, capability и доменная модель

- [ ] 1.1 Добавить capability `crawler-proxy-pool` в `capabilities` контекста `integration-platform` в `architecture/domain-catalog.yaml`; проверить `go -C tools/archlint run .`
- [ ] 1.2 Обновить `docs/domain-model.md` (capability matrix) и затронутые диаграммы; проверить `go -C tools/archlint run .` и рендеринг диаграмм

## 2. Разведка Crawl4AI (spike)

- [ ] 2.1 Сверить по документации версии контейнера: HTTP API (scrape/crawl/map/seed), формат `ProxyConfig` и ротации, поддержку и формат robots.txt, способ передачи `LLMExtractionStrategy`; зафиксировать выводы в `design.md` (Open Questions → Decisions / Risks); проверка — обновлённый `design.md` и рабочий `curl` к локальному контейнеру
- [ ] 2.2 Поднять контейнер Crawl4AI локально и выполнить smoke-запрос реальной страницы; проверка — вернулся непустой Markdown, JS-страница отрендерилась
- [ ] 2.3 Проверить поведение движка с прокси (`ProxyConfig`): запрос через один прокси проходит; проверка — лог контейнера показывает использование прокси

## 3. Контейнер, развёртка и конфигурация

- [ ] 3.1 Добавить сервис Crawl4AI в `compose.yaml` (образ, порт, healthcheck); проверка — `docker compose up` поднимает сервис, healthcheck зелёный
- [ ] 3.2 Описать сервис/роль в `deploy/services.yaml`; проверка — конфигурация загружается без ошибок

- [ ] 3.4 Обновить `.env.example` образцом переменных; проверка — конфигурация валидна и запускается без ключей

- [ ] 4.2 Реализовать часть `search.Port`; проверка — контрактный suite `contracttest` против фейкового сервера движка
- [ ] 4.3 Реализовать часть `crawl.Port` (`Crawl`/`Extract`); проверка — контрактный suite `contracttest`

- [ ] 4.5 Маппинг навигации по релевантности (`IncludePaths`/`ExcludePaths` → стратегия движка); проверка — unit-тест маппинга на фикстурах

## 5. Прокси-пул (`crawler-proxy-pool`)

- [ ] 5.1 Объявить интерфейс `Source` и тип `Proxy` (URL, Tier, источник); проверка — unit-тесты типов и валидации
- [ ] 5.2 Реализовать статический источник (разбор env-списка, назначение уровней `cheap`/`premium`); проверка — unit-тесты разбора, учётные данные не попадают в логи
- [ ] 5.3 Реализовать политику выбора: выбор дешёвого уровня, sticky per registrable domain, эскалация на премиум при блокировке; проверка — unit-тесты по сценариям спеки
- [ ] 5.4 Реализовать здоровье и карантин прокси с возвратом по таймауту; проверка — unit-тесты карантина и возврата
- [ ] 5.5 Впрыскать выбранный прокси в запросы адаптера (`ProxyConfig`) и вести учёт по источнику/уровню; проверка — интеграционный тест на фейковом движке
- [ ] 5.6 Подтвердить расширяемость под провайдера: тестовая вторая реализация `Source` работает без правки политики; проверка — unit-тест с двумя источниками

- [ ] 6.2 Реализовать фильтр robots в адаптере (при включённом режиме — соблюдение, при выключенном — обход); проверка — unit-тесты на фикстурах `robots.txt`
- [ ] 6.3 Отобразить режим в журнале/карточке задания; проверка — golden-тесты шаблонов
