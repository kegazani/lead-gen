## Why

Краулер среза `mvp-lead-search` — hosted **Firecrawl**: ключ и кредиты чужого облака, ротация IP на стороне провайдера, robots.txt — поведение движка, которым мы не управляем. Нужен собственный движок, который запускается рядом с платформой, не зависит от доступности и лимитов внешнего API и даёт нам контроль над прокси, правилами доступа и стоимостью. **Движок — self-hosted Crawl4AI** (Apache-2.0) в контейнере за существующим `crawl.Port`/`search.Port`: JS-рендер, Markdown, навигация по релевантности и экстракция становятся нашими адаптерными механизмами, а ядро (`RunSearch`, домен, консоль) не меняется.

## What Changes

- **Движок краулинга — self-hosted Crawl4AI** (Apache-2.0, контейнер) за тем же портом. Наш Go-код — HTTP-клиент к контейнеру, нормализация результата, дедупликация. **Firecrawl остаётся альтернативным адаптером:** выбор движка — конфигурацией, без правки ядра.
- **Прокси-пул** (новая capability `crawler-proxy-pool`): источники прокси (статический список сейчас, провайдер позже — один интерфейс), уровни `cheap`/`premium`, ротация, привязка к домену (sticky), отслеживание здоровья с карантином, эскалация «дёшево → премиум» при блокировке. Заложена возможность комбинировать дешёвые списки с дорогим провайдером.
- **robots.txt управляется конфигурацией.** Соблюдение правил доступа становится поведением нашего адаптера, а не движка: включается и выключается флагом, **по умолчанию — выключено** (обход без проверки robots.txt), с фиксацией решения в журнале задания. **BREAKING** для требования `osint-enrichment` «Соблюдение правил доступа и сдерживание нагрузки» (было: `SHALL` соблюдать robots.txt).
- **LLM-экстракция и OCR.** Эскалация на LLM идёт через `llm.Port` (DeepSeek), а не через hosted `extract`; OCR (email в картинках) — отдельный источник текста перед экстракцией (по `docs/crawl4ai-playbook.md`).
- **Лимиты вместо кредитов.** Self-hosted обход не расходует кредиты Firecrawl: вместо них — собственные лимиты параллелизма, частоты и глубины. Кредитный бюджет (`firecrawl-credit-budget`) остаётся только у Firecrawl-адаптера.
- **Развёртка.** Контейнер Crawl4AI в `compose.yaml` и `deploy/services.yaml`, конфигурация прокси и robots — через env, секреты вне репозитория.

## Capabilities

### New Capabilities

- `crawler-proxy-pool`: пул прокси для обхода — источники (статический список, провайдер), уровни стоимости, ротация и привязка к домену, здоровье и карантин, эскалация на премиум при блокировке; владелец — `integration-platform`.

### Modified Capabilities

- `osint-enrichment`: соблюдение robots.txt перестаёт быть безусловным (`SHALL`) — управляется конфигурацией, по умолчанию обход идёт без проверки robots.txt; решение фиксируется в журнале задания.

> **Зависимость.** Основная спека `osint-enrichment` ещё не в `openspec/specs/`: она создаётся дельтой ADDED в незаархивированном change'е `mvp-lead-search`. MODIFIED-дельту этого change'а нужно применять после архивации `mvp-lead-search` (иначе некуда накладывать изменение).

## Impact

**Затрагиваемые bounded contexts:**

- `integration-platform` — первичный: новый адаптер `crawl4ai` за `crawl.Port`/`search.Port`, прокси-политика (`crawler-proxy-pool`), robots-фильтр, лимитер. Каталог: capability `crawler-proxy-pool` добавляется в список контекста.
- `lead-management` — потребитель: `RunSearch` без изменений логики (граница порта сохранена); возможная правка конфигурации движка и лимитов.
- `data-governance` — задет robots-флагом косвенно (правило «без обхода защит» из каталога): отклонение фиксируется в design; при наличии юридического гейта — согласовать.

**Доменная модель:** новых агрегатов и domain events нет. Добавляется capability `crawler-proxy-pool` — обновляются `architecture/domain-catalog.yaml`, `docs/domain-model.md` и диаграммы владения в этом же change (иначе `archlint` падает).

**Код:** новый пакет адаптера `backend/contexts/integration-platform/internal/adapters/crawl4ai`; прокси-политика там же; контракт `contracts/integration-platform/crawl` без изменения формы (возможно расширение `Request` опциональными полями прокси/robots); конфигурация и сборка в `backend/cmd/lead-gen`.

**Зависимости:** контейнер **Crawl4AI** (Apache-2.0, Python + Playwright) — внешний self-hosted сервис; прокси-провайдер пока не обязателен (статический список). Новых Go-зависимостей не требуется — HTTP-клиент на stdlib.

**Проверка:** контрактный suite портов против фейкового сервера Crawl4AI; unit-тесты прокси-политики (выбор уровня, карантин, эскалация), robots-фильтра, лимитера; e2e «запрос → обход → карточки» на тестовом движке; `make check` и `go -C tools/archlint run .` зелёные; приёмка на реальных сайтах.

**Риски:** блокировки и качество прокси (смягчение — уровни, карантин, эскалация); юридический риск игнора robots.txt по умолчанию (осознанное отклонение, фиксируется в design); ресурсоёмкость Playwright в контейнере (CPU/RAM, параллелизм); расхождение качества экстракции с Firecrawl (смягчение — слои + LLM-эскалация + метрика «доля страниц с контактами»).
