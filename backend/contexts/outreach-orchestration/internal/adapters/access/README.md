# access

Минимальный адаптер порта `ports.AccessDecision` для среза
`outreach-approval-slice` (задача 5.3).

## Это заглушка среза

Реализация проверяет **только** наличие явно выданной пары `(tenant, actor)` в
списке разрешений. Положительный ответ означает «оператору разрешено
действовать в этом тенанте в рамках среза», а **не** «оператор вправе
выполнить конкретное действие».

Здесь сознательно отсутствуют:

- роли, группы, наследование прав;
- политики на уровне ресурса или действия (например, «утверждать черновики»);
- чтение claims, токенов и любого внешнего источника идентичности;
- аудит и кэширование решений.

## Что остаётся за `platform-governance`

Полная политика RBAC, модель ролей и выдача прав принадлежат контексту
`platform-governance`. Этот пакет подключается как временная реализация порта,
чтобы use cases среза работали и проверялись; заменять его на реальный
адаптер нужно без изменения домена и прикладного слоя — только в
`internal/composition`.

## Поведение

- `NewDecider()` — пустой список; по умолчанию доступ запрещён.
- `Grant(actor, tenant)` — выдать право; пустые значения отвергаются
  (`ErrMissingSubject`).
- `CanAct(actor, tenant)` — `(true, nil)` при наличии права, `(false, nil)` при
  его отсутствии, `(false, ErrMissingSubject)` при пустых акторе или тенанте.
- Граница тенанта явная: пара из другого тенанта права не даёт.
