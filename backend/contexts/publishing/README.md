# Контекст `publishing`

Публикация утверждённых материалов через официальные API площадок
(`architecture/domain-catalog.yaml`, capability `digest-publishing`). Контекст
берёт выжимку сообщества как источник, принимает материалы под каждую площадку,
проводит их через утверждение человеком и исполняет публикацию вовне — только
через официальный интерфейс площадки.

Публикация — необратимое исходящее действие, поэтому домен требует утверждения
человеком до исполнения (policy `approved-publication-only`), а сам внешний вызов
находится за портом. Instagram/Meta в набор площадок не входит: канал выведен из
объёма по правовому основанию, а не по способу доступа.

## Слои

```
publishing/
  service.go                 сборка сервиса и роли (единственное место сборки)
  contract.go                прямые адаптеры публикуемых контрактов
  internal/domain            агрегат publication, VO, события, инварианты
  internal/ports             репозиторий, транзакция, часы, порты площадки и выжимки
  internal/app/command       приём команды, утверждение, отклонение, исполнение
  internal/app/query         чтение публикации и очереди по статусу
  internal/adapters/...      in-memory репозиторий, outbox, адаптеры площадки и выжимки
```

Домен не зависит от прикладного слоя и адаптеров. Межконтекстные связи — только
через `contracts/`; сырых сообщений и данных авторов контекст не видит по
структуре (design.md, Решение 3).

## Домен

Агрегат **`publication`** — один материал под одну площадку.

- value objects: **`publication-target`** (площадка + учётная запись платформы,
  закрытый набор `dzen`/`linkedin`/`telegram`), **`publication-status`**
  (`draft → approved → queued → published / failed / rejected`);
- инварианты: публикуется только утверждённая версия; терминальное состояние не
  меняется; повтор с тем же `idempotency key` не создаёт вторую публикацию;
- событие: **`material-published`** (единственное доменное событие; отказ
  площадки фиксируется состоянием, а не выдаётся за публикацию).

Материал готовится под формат площадки и сокращается до её предела с признаком
`shortened`.

## Use cases

| Сценарий | Что делает |
|---|---|
| `command.RequestPublication` | принимает `publication-command`: проверяет выжимку-источник, создаёт по черновику на материал, идемпотентно по ключу |
| `command.Approve` / `command.Reject` | утверждение и отклонение человеком с автором и временем |
| `command.Publish` | проверяет готовность канала, вызывает порт площадки, фиксирует `published`/`failed`; сбой транспорта состояние не меняет |
| `query.GetPublication` / `query.PublicationQueue` | чтение проекции и очереди по статусу |

## Порты и адаптеры

- `PublicationRepository`, `UnitOfWork`/`Outbox` — in-memory адаптеры (снимки
  состояния, оптимистичная блокировка, transactional outbox);
- `PlatformPublisher` — публикация вовне: **`Unavailable`** (честный отказ) и
  **`Deterministic`** (детерминированный in-memory, без сети; умеет задавать
  отказ площадки и неготовность канала);
- `DigestSource` — источник выжимки: **`Unavailable`** и **`Memory`**.

Реальные официальные API площадок подключаются отдельным адаптером
интеграционной платформы (`provider-port`) без изменения контекста.

## Контракты

- `contracts/publishing/publicationcommand` — команда на публикацию;
- `contracts/publishing/publicationresult` — чтение исходов публикации.

Прямые (in-proc) адаптеры контрактов — `NewPublicationCommand` /
`NewPublicationResult` / `NewContracts` в `contract.go`.

## Роли

| Роль | Поведение |
|---|---|
| `api` | HTTP-сервер: команда, утверждение, отклонение, исполнение, чтение, `GET /healthz` |
| `worker` | relay outbox: доставка `material-published` потребителям (если задан `Publisher`) |
| `schedule` | тик без действий: расписание не публикует (design.md, Решение 5) |

## Что осталось заглушкой

- **Официальные API площадок** — за портом; в срезе недоступный и
  детерминированный адаптеры, реальной сети нет.
- **Генерация/переработка текста** (capability `linguistics`) — материал
  принимается подготовленным под площадку; переработка и запрет дословных цитат
  выполняются вне этого контекста.
- **Порог по размеру сообщества, проверка персональных данных, ограничение
  частоты** (`queued`) — статус `queued` объявлен доменом, но политика очереди и
  проверки перед публикацией не подключены.
- **Подготовка по расписанию** — требует генерации материала; роль честно
  сообщает о неготовности и ничего не публикует.
- **Контракт `community-digest`** — источник выжимки за портом; контракт
  сообщества в workspace ещё не наполнен.
